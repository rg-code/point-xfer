# point-xfer

Mobile-first web app that maps credit card and loyalty point transfer partners, plus a GitHub Action that tracks live transfer bonuses from public blog RSS feeds. Static site on GitHub Pages; no build step, no runtime dependencies.

## Commands

```sh
npm test               # node:test suite (parser, merge logic, dataset integrity). Run after every change.
npm run serve          # local server; index.html can't be opened from disk (fetch of local JSON is blocked)
npm run preview        # dist/preview.html: single self-contained file with data, CSS and JS inlined
npm run track          # fetch feeds and update data/promotions.json
npm run track:dry      # same, print only
npm run track:offline  # re-merge data/promotions.manual.json and prune expired, no network
```

Node 20+ (CI uses 22). There is no package install step; keep it that way unless there's a strong reason.

## Layout

- `robots.txt` lets search engines in and asks AI training crawlers (GPTBot, ClaudeBot, CCBot, Google-Extended, Applebot-Extended, Bytespider, ...) and SEO-tool crawlers (AhrefsBot, SemrushBot, ...) to stay out; covers /museum_problem/ and /inkling/ too. AI assistants and AI search indexers (ChatGPT-User, OAI-SearchBot, Claude-User, Claude-SearchBot, Perplexity-User, PerplexityBot, ...) may read pages but not `/museum_problem/data/` or `/inkling/data/`; search engines keep full access because Google renders the JavaScript and needs those files. `sitemap.xml` lists /, /museum_problem/ and /inkling/. Both are copied into the site by `pages.yml`.
- `404.html` the site's not-found page (the same GIF and wording as rohitkgupta.com's 404, in this site's colors and theme). GitHub Pages serves it for any missing path, including under /museum_problem/, so it uses absolute URLs only. Image is `assets/404.gif`.
- `art-gallery-problem/index.html` redirect to /museum_problem/, a nod to the art gallery problem (the reason for the museum finder's path name). `pages.yml` publishes it at /art-gallery-problem/, /art_gallery_problem/, /Art-gallery-problem/ and /Art_gallery_problem/.
- `index.html` app shell. Loads D3 7.9.0 from cdnjs and B612 from Google Fonts. Contains a small pre-paint script that applies the saved theme. Footer opens with a short support line linking to PayPal (`paypal.me/soulrg`, GoatCounter click `paypal-footer`; a shorter take on the museum finder's own support message), then the verified date and report link beside a link to the museum finder at /museum_problem/ (`.foot-row`, with a small ✈ between them that hides once they wrap; tagged `?utm_source=home` so GoatCounter shows visits from here as referrer "home"), then a line linking to Inkling at /inkling/ (also `?utm_source=home`, GoatCounter click `inkling-footer`), and at the bottom, centered under a rule, a small © year (filled in by app.js) + CC BY-NC-ND 4.0 license line; this is a personal tool, so no disclaimers.
- `assets/app.js` single IIFE, vanilla JS. Sections: data loading and indexing, URL state, controls, bonus strip, route view (D3 rail), compare view (D3 matrix), detail sheet (calculator), partner search, theme toggle, easter eggs. The detail sheet shows per card: ratio, live bonus with ranked sources, transfer time and minimum, go/wait verdict, bonus history chart. Opens on By card with "All cards" (`state.from = ALL`): every partner at its best route across currencies (or the lit card's route), colored line tags naming the cards that reach it, the sheet showing every card (lit card first); `oneCard()` is the currency in view, null for All cards and Compare. URL params: `from` (By card for that currency; omitted for All cards), `view` (`compare`; `routes` is still read), `type`, `bonus`, `partner` (open detail sheet, so partners are linkable), `line` (All cards only: the lit card), `layout` (`strip`, `terminal` or `rings`, All cards only; omitted = rings from 720px up, strip on phones, the one layout that fits a phone without scrolling sideways; the old `circle` value opens the terminal). Source tags the visitor arrived with (`source`, `ref`, `src`, `utm_source`, `utm_medium`, `utm_campaign`, `campaign`) are kept by `writeURL()`, because GoatCounter reads the address only when the page finishes loading, after the first rewrite; the museum finder's footer link uses `?source=mu`.
- `assets/advice.js` go/wait engine. Plain script (no import/export) that sets `globalThis.transferAdvice`, so the browser and node tests share it. Estimates the chance of a bonus within 90 days from the gaps between past bonuses, smoothed toward the route's average rate (average rate alone with fewer than 3 comparable gaps). Chance × typical bonus = value of waiting. Live bonus: Go if it beats the value of waiting or the typical size. No live bonus: Wait only if waiting is worth ≥ 10% and the chance is ≥ 40%, otherwise Go. Targeted offers (`targeted: true`) are drawn faded and ignored by the math. The window starts at the later of `historySince` and the route's `added` date. `tests/insights.test.mjs` pins the behaviour; run a survey over all routes after changing constants.
- Easter eggs: typing a word from `EGGS` in app.js (outside text fields) plays it. `lee` drops `assets/eggs/lee.webp`, which bounces on the bottom edge (a plain fade with reduced motion). The egg is a `popover` so it shows above open dialogs; it's exempt from the one-animation rule. Keep egg images small WebP (resize before committing); the preview build inlines anything under `assets/eggs/` referenced from app.js.
- `assets/styles.css` design tokens at the top, mobile-first, `@media (min-width: 720px)` and `1000px` breakpoints (controls use the two-row layout from 720 to 1079px), dark mode.
- `data/programs.json` currencies (dropdown order = column order in Compare = line order on All cards), alliance groups, partners. `minTransfer` / `increment` may be `null` when the issuer publishes none (U.S. Bank); the sheet then says "Minimum not published".
- `data/transfers.json` every route. `ratio` is `[points sent, points received]`; `[5, 4]` means 1,000 → 800. Optional `note` and `variants` (card-dependent ratios, see chase → hyatt), `time` (`{ min, max, unit }`, `max: 0` = instant) and `timeNote`, `min` / `increment` / `minNote` when a route differs from the currency's `minTransfer` / `increment` in `programs.json`, and `added` (ISO date) for routes launched after the archive's `since`. Notes are short user-facing caveats, not research annotations. Bump `verifiedOn` when you re-check the list.
- `data/promotions.json` written by the tracker. Don't hand-edit; edit `promotions.manual.json` and run `npm run track:offline`.
- `data/promotions.manual.json` `add` (hand-entered bonuses, always win while active) and `suppress` (promo ids to hide false positives, e.g. `citi-turkish-25`).
- `data/promotions.archive.json` hand-researched past bonuses from `since` onward (`records`: from, to, bonus, start, end, sources, confidence, optional `targeted`, `note`). Built mainly from Frequent Miler's past-bonus table checked against each article and AwardWallet; Bilt Rent Day tiers from Bilt's terms PDFs; `bonus` is the base tier. Merged into `history` by the tracker; curated records beat overlapping tracker records. Rerun `npm run track:offline` after editing.
- `data/sources.json` RSS feeds the tracker reads.
- `scripts/lib/parse.mjs` feed parsing and bonus extraction: alias tables for currencies and partners, bonus %, end-date parsing, official offer links from post bodies.
- `scripts/lib/sources.mjs` official domains per program and `rankSources`: official page, then AwardWallet, then Frequent Miler and Doctor of Credit (tied), then the rest. Add a domain here when adding a program.
- `scripts/track-promos.mjs` tracker entry point and `merge()` logic (exported for tests).
- `scripts/lib/slack.mjs` Slack message for new bonuses: an opener addressed to a random name from `PEOPLE` (general `LINES` with `{name}`, plus `PERSONAL` lines for one person only), then one line per bonus linking only to milesmaximizer.com (never to blog sources). A bonus announced before its `start` gets a second post (`LIVE_LINES` openers) on the first run once it is live by the US Eastern date (`merge()` returns it in `goingLive` and sets `livePosted` so it posts once); announced on the day, found late or manual → one post. Posted as Rohit by `track-promos.yml` with the `SLACK_USER_TOKEN` secret (user token, scope `chat:write`) to the `SLACK_CHANNEL_ID` variable. Names are plain text, not @mentions, so nobody is pinged. Keep openers harmless; `tests/slack.test.mjs` checks every line names someone on the list.
- `scripts/build-preview.mjs` builds the single-file preview.
- `tests/tracker.test.mjs` parser, merge and dataset tests. `tests/insights.test.mjs` source ranking, archive merge, advice engine, time/minimum and archive data checks.
- `.github/workflows/track-promos.yml` cron every 2 hours: test, track, commit if changed, post new bonuses to Slack (skipped if not configured, never fails the run), open an issue for new bonuses.
- `.github/workflows/pages.yml` deploy on push and on tracker completion. It also checks out `rg-code/museum-reciprocal-finder` (private; read with the read-only deploy key in the `MUSEUM_DEPLOY_KEY` secret, falling back to `github.token` while the repo is public) and publishes that app (its `index.html`, `manifest.webmanifest`, `sw.js`, `icons/`, `fonts/`, and `data/` with museums, programs and memberships packed into `.bin` files by its `tools/pack-data.mjs`; plain JSON for those three is never published) at `/museum_problem/`, so the museum finder refreshes on every deploy here. Its service worker is scoped to `/museum_problem/` only. Don't add a root-scoped service worker to this site, or it would intercept that path. It also checks out `rg-code/RInkU` (private; read-only deploy key in `INKLING_DEPLOY_KEY`, sparse checkout of `site/`) and publishes Inkling's `site/` at `/inkling/`, minus its own 404.html. The `?v=<sha>` stamp is applied to Inkling's `index.html` and to the module imports in its JS, using RInkU's commit. Inkling's data updates once a day, so it's live here within one tracker cycle.
- `.github/workflows/slack-check.yml` manual: checks `SLACK_USER_TOKEN` with `auth.test` and posts a test message to your own DM (or the channel). Run it after replacing the token.

## How the tracker decides what's a bonus

1. Headline must mention transfer/convert, contain a `NN% bonus`, and name a currency. Devaluations are never bonuses: `isDevaluation()` drops posts saying devalue, ratio/transfer change, "from 1:1 to 4:3" (headline or summary lead) or cut/reduce/no longer/worse (headline only), and "need/require/cost NN% more" is not read as a bonus. Added after TPG's "Bilt members will soon need 33% more points" post became a false `bilt-hyatt-33` (Oct 1, 2026, now in `suppress`).
2. Targets come from the part of the headline after " to " / " into " / "→".
3. Every (currency, partner) pair must exist in `transfers.json`, otherwise it's dropped. This is the main false-positive filter, so adding a route also teaches the tracker about it.
4. End date from "through Sept. 30", "until October 15", "ends 9/30". Rent Day ("Rent Day" anywhere, or a Bilt headline naming "<Month> 1") gets `start` = `end` = the nearest 1st of the month, so previews stay hidden until the day and last month's posts at the same % don't merge in; not-yet-started bonuses stay in `promotions` (browsers filter by `start`). Other one-day offers ("today only") end on the publish date. No date found → kept 30 days (`assumedEnd`).
5. `[Expired]` headlines close out a matching bonus. Manual entries are not closed by feed results.
6. Sources are sorted official → AwardWallet → Frequent Miler = Doctor of Credit → others. Official links found in a post body are added as sources. When sources disagree on an end date, the better-ranked one wins (`endSource`).
7. Writes only when data changes, so the Action doesn't make noise commits.

When adding a partner or currency, add aliases in `parse.mjs` and a test with a realistic headline. Watch for collisions: "American Express" vs American Airlines, "Rove" vs "Rover", "Miles & More" vs "Miles&Smiles", case-sensitive `ANA`, `BA`, `EVA`, `TAP`, `SAS`, `JAL`.

## Design rules

- Subject vernacular is airline route maps: each currency is a trunk line, partners are stops. Branch stroke weight = partner points per 1,000 sent (log scale, `weight` in app.js). Compare view dot area = same value (sqrt scale, `dotR`).
- All cards (`drawLines` in app.js) is a transit map after fan-made ones (Cerovic, Booth, Vignelli): bold lines with gaps, one per currency in dropdown order, colored by `--line-<id>` tokens in styles.css, each running from its first to its last station; a white station with an ink ring on a line = that card transfers there (yellow = that card has the live bonus); a row with several stations is an interchange, its stations joined by a white connector, and a line running through a connector without stopping bridges over it with a `--haze` gap each side (with a card lit, connectors fade and only the lit line keeps its bridges); faint row guides tie stations to rows. Each row names its lines with colored tags (`.line-tag`, never color alone). Sticky `.line-chips` under the controls light one line (`state.line`, URL `line`): other lines and stations fade, unreached rows dim, and lit rows show that card's rate. No weight encoding here (the rate is in the row); on phones the rate sits under the name to give the rail room. The palette is the dataviz reference hues minus yellow (`--bonus` owns it), ordered so neighbours pass the adjacent CVD/normal-vision checks in both modes on `--haze` (light worst CVD ΔE 7.2, floor band, hence the card names in every row and the key); Rove rides `--muted` slate because a 9th hue is never generated. A new currency needs a `--line-<id>` in `:root` and both dark blocks, and a re-run of the validator; otherwise it falls back to `--route`.
- All cards also has a terminal layout (`renderTerminal` / `drawTerminal` in app.js), an airport terminal map picked with the Strip / Terminal switch (`state.layout`). It replaced a concentric-circle layout the owner didn't like. A long terminal building has one concourse (pier) per alliance group, lettered by `D.groups` order (A Star Alliance, B oneworld, C SkyTeam above; D other airlines, E hotels below; with filters, the first 3/5 of the shown groups go above). Partners are gates numbered from the terminal out; `gateCode()` numbers them by name among every partner in the group, so filters never renumber a gate. Each card is a colored walkway lane down the concourses it serves, out to its last gate there, with stations at its gates (yellow = that card's live bonus). Gate codes are yellow when any card has a live bonus there. Long names wrap to two lines. The terminal is a departures board (`.terminal-board`) for the hovered or focused gate. Gate rows are focusable and open the sheet. Drawn at least 760px wide, so on phones it scrolls sideways (the strip stays the phone default). The line chips work the same as on the strip.
- All cards also has a rings layout (`renderRings` / `drawRings` in app.js), the third option on the Strip / Terminal / Rings switch. Each card is an open arc of at most three quarters of a circle (dropdown order, innermost first), running only from its first partner to its last. Partners sit around a 270° fan in alliance sectors with names outside, each sector ordered by how many cards reach the partner (most first, so Flying Blue leads SkyTeam), then A to Z. A small dot in the card's color marks a transfer (yellow = live bonus). The open quarter at the bottom names each ring at its radius. It's quiet on purpose: no guides, and only the partner in focus gets a spoke. Clicking a ring or its name lights that card (`state.line`, same as the chips): its arc thickens and its dots turn white, and the rest fades. The center `.rings-board` shows the partner in focus. Partner wedges are focusable and open the sheet. Drawn at least 700px wide (phones scroll sideways).
- One accent: taxiway yellow `--bonus` marks live bonuses only. Don't use it for anything else. Past bonuses in the history chart use `--route`; the Go verdict is ink-filled, Wait is outlined.
- Typeface is B612 (Airbus cockpit font) at 400/700 only. Type scale uses the `--step-*` tokens.
- Tokens live in `:root`; dark values are duplicated in `[data-theme="dark"]` and the `prefers-color-scheme` block. Change both.
- Mobile first. Tap targets ≥ 44px, the currency picker is a native `<select>` (18px font so iOS doesn't zoom), controls are sticky, detail view is a `<dialog>` bottom sheet with swipe-to-close.
- Partner search is a top-pinned `<dialog>` (so the on-screen keyboard doesn't cover results) opened from the button beside the view tabs or `/`. It's an ARIA combobox matching word prefixes in partner name, id and `note`, so notes double as search keywords ("Avios", "Alaska"). Picking a result opens the detail sheet.
- One orchestrated animation (rail draws on currency change). Respect `prefers-reduced-motion`.
- Prose UI copy: sentence case, no middle-dot separators, no eyebrow labels.

## Gotchas

- The preview build sets `window.__NO_STORAGE__ = true`; the app must work without `localStorage` (Claude.ai artifact sandboxes block it). Guard any new storage use the same way.
- The rail is drawn from measured DOM row positions. Anything that changes row height after render (fonts, wrapping) needs `drawRail(false)`. Redraw on resize only fires on width changes, deliberately, so the intro animation isn't cancelled.
- `history.replaceState` is wrapped in try/catch for sandboxed previews.
- Commits made by `GITHUB_TOKEN` don't trigger `push` workflows. `pages.yml` listens for `workflow_run` of "Track transfer bonuses"; if you rename that workflow, update the reference.
- The site is served at milesmaximizer.com (custom domain on GitHub Pages, DNS at NameSilo, no Cloudflare). The old rohitkgupta.com/point-xfer/ and rg-code.github.io/point-xfer/ URLs redirect there as long as the rg-code.github.io repo keeps rohitkgupta.com as its domain. GitHub serves everything with `max-age=600`, so `pages.yml` stamps `?v=<sha>` onto the CSS/JS links in the deployed `index.html` to keep them in step with the HTML after a deploy; any new script or stylesheet must be added to that `sed` pattern. The "Report a mistake" link reads the repo from `user.github.io/repo/` URLs; custom domains need an entry in `CUSTOM_DOMAINS` in app.js.
- GitHub Pages on a private repo needs a paid plan. Scheduled workflows pause after 60 days of repo inactivity.
- Browsers compute "live" bonuses using the visitor's local date, so an expired bonus disappears on time even if the Action hasn't run.

## Data sources

Ratios were verified on 2026-09-23 against issuer pages and recent coverage (The Points Guy, Upgraded Points, One Mile at a Time, Frequent Miler, AwardWallet, Rove's own site). U.S. Bank was added on 2026-10-06 (launched about Aug 11, 2026; five partners: Flying Blue, Qantas, Ethiopian, Avianca 1:1 and Accor 2:1; only the closed Altitude Reserve and FlexPerks Travel cards transfer; partners were pulled and restored in its first weeks, so re-check it first). Recent changes worth remembering: Bilt → Hyatt goes from 1:1 to 4:3 on Jan 1, 2027 (on or after that date set its `ratio` to `[4, 3]` and drop the note); Citi added JAL (Sep 20, 2026) and cut I Prefer to 1:2 and Choice to 1:1.5 (Apr 19, 2026); Citi dropped Aeromexico (Jan 2026); Amex dropped Etihad (Jun 30, 2026); Chase dropped Emirates and moved Hyatt to 4:3 on Sapphire Preferred / Ink Preferred. Transfers are irreversible, so accuracy beats coverage: when unsure, leave a route out and add a `note`.
